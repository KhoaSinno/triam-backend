Quy trình tái lập đánh giá thực nghiệm TRIAM

Tài liệu mô tả dữ liệu đầu vào, thứ tự chạy script, đầu ra và chi phí của quy trình đánh giá hiện tại.

Nguyên tắc: Không sửa các log gốc hoặc file dữ liệu 60 ca. Dataset provenance-checked là file dẫn xuất để chấm điểm; nó không thay thế dữ liệu gốc.

1. Dữ liệu đầu vào

Vai tròFileNội dung
Dataset gốclogs/ragas_eval/production_flow_trace.json60 câu hỏi, response, reference, context và liên kết đến log.
Log gốclog_live_context_*.mdSự kiện AGENT_TRACE để xác minh retrieval và tính latency.
Log đã parselogs/ragas_eval/parsed_live_logs.jsonNguồn ưu tiên của báo cáo latency; script có thể quét lại log gốc khi cần.

2. Flow thực thi

Dữ liệu gốc

production_flow_trace.json + log_live_context_*.md

Bước 1 — Kiểm tra provenance Không tốn phí

scripts/ragas_dataset_validation.py
Đối chiếu context với đúng trace và chunk retrieval của lượt hỏi.

Dataset khóa để đánh giá

production_flow_trace_provenance_checked.json
production_flow_trace_provenance_checked.manifest.json

Bước 2 — LLM-as-a-Judge, chạy 3 lần Có phí Gemini

tests/eval_llm_as_judge.py
Chấm Answer metrics trên các ca hợp lệ; metric retrieval chỉ áp dụng cho ca có provenance được xác minh.

Bước 3 — Latency thành phần Không tốn phí

tests/eval_latency_budget.py
Báo cáo Semantic Grounding, Query Guard, Retrieval, Web Search và Tool Execution. Không báo cáo Voice Turn Total.

3. Lệnh chạy tái lập

Chạy từ thư mục gốc triam-backend.

# 1. Tạo lại dataset provenance-checked và manifest
uv run python scripts/ragas_dataset_validation.py

# 2. Tái lập bảng latency thành phần
uv run python tests/eval_latency_budget.py

# 3. Chấm LLM-as-a-Judge ba lần độc lập
uv run python tests/eval_llm_as_judge.py
uv run python tests/eval_llm_as_judge.py
uv run python tests/eval_llm_as_judge.py

Nếu dataset provenance-checked và manifest còn nguyên, bước 1 có thể bỏ qua. Bước judge vẫn cần ba lần chạy nếu muốn tái lập bảng trung vị trong luận văn.

4. Phạm vi metric

Metric chất lượng câu trả lời

Answer Relevancy và Answer Correctness dùng câu hỏi, response và reference hợp lệ.

Metric retrieval/RAG

Context Precision, Context Recall và Faithfulness chỉ dùng các ca có context được xác minh thuộc đúng retrieval trace. Với dataset hiện tại: 11/60 ca.

Latency

Chỉ dùng trace phía máy chủ và báo cáo latency theo thành phần. Không dùng để kết luận độ trễ đầu-cuối trên thiết bị.
